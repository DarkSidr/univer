# Лабораторная работа №1. Анализ и исследование проблем

## Тема проекта

Персональный менеджер задач (Todo List) с категориями.

Будущий прототип: консольное приложение на .NET для управления личными задачами. Пользователь сможет создавать, просматривать, редактировать и удалять задачи, распределять их по категориям "Работа", "Учеба", "Личное", отмечать выполнение и сохранять данные в JSON-файл.

## Цель исследования

Понять, как потенциальные пользователи сейчас фиксируют и контролируют личные задачи, какие проблемы возникают при планировании, какие функции действительно нужны в минимальном прототипе, а какие можно отложить.

## CustDev: вопросы для проблемного интервью

1. Как вы сейчас записываете и контролируете свои задачи на день или неделю?
2. В каких ситуациях вы чаще всего забываете о задачах или сроках?
3. Что вам неудобно в текущем способе планирования?
4. Разделяете ли вы задачи по сферам жизни: учеба, работа, личное? Если да, как именно?
5. Как вы понимаете, что задача завершена: просто вычеркиваете ее, переносите в архив или не фиксируете это?
6. Пользуетесь ли вы дедлайнами и напоминаниями? В каких случаях они помогают, а в каких мешают?
7. Какие функции в менеджерах задач кажутся вам лишними или слишком сложными?

## Интервью 1

Респондент: студент магистратуры, совмещает учебу и подработку.

Текущий способ: заметки в Telegram "Избранное", иногда бумажный список на день.

Основные тезисы:

- Задачи появляются из разных источников: сообщения преподавателей, рабочие чаты, личные дела.
- Частая проблема - задачи теряются в переписках и заметках без структуры.
- Пользователь хочет быстро записать задачу, не заполняя много полей.
- Категории "Учеба" и "Работа" важны, потому что помогают переключаться между контекстами.
- Дедлайн нужен не всегда, но для учебных заданий и рабочих задач он критичен.
- Сложные приложения с большим количеством настроек пользователь быстро бросает.

Инсайт: для MVP важны быстрый ввод, категории и дедлайн, но интерфейс должен оставаться простым.

## Интервью 2

Респондент: знакомый, работает в офисе, ведет личные задачи отдельно от рабочих.

Текущий способ: Microsoft To Do для рабочих задач, бумажные стикеры для личных дел.

Основные тезисы:

- Рабочие задачи удобно хранить в цифровом виде, потому что их можно редактировать и переносить.
- Личные задачи часто записываются на бумаге, потому что это быстрее.
- Проблема цифровых инструментов - лишние функции, уведомления и необходимость авторизации.
- Пользователь хотел бы видеть простой список задач по категориям без сложной регистрации и синхронизации.
- Статус "выполнено" нужен, чтобы видеть прогресс за день.
- Описание задачи полезно только для крупных задач; для мелких достаточно названия.

Инсайт: локальное приложение без регистрации и синхронизации может быть удобным для пользователей, которым нужен простой личный список дел.

## Обобщенные выводы по интервью

- Пользователям нужен быстрый способ зафиксировать задачу.
- Разделение по категориям помогает не смешивать учебные, рабочие и личные дела.
- Дедлайны нужны выборочно, но должны поддерживаться.
- Статус выполнения важен для контроля прогресса.
- Избыточные функции, регистрация и сложные сценарии снижают вероятность регулярного использования.
- Минимальный прототип должен решать базовую проблему: "записать, найти, выполнить, не забыть".

## Jobs To Be Done

Когда у меня появляются учебные, рабочие и личные задачи из разных источников, я хочу быстро записать их в один список, разложить по категориям и видеть ближайшие дедлайны, чтобы не держать все в голове и не забывать важные дела.

## Конкурентный анализ

| Конкурент | Сильные стороны | Слабые стороны | Возможности для нашего прототипа | Угрозы |
| --- | --- | --- | --- | --- |
| Microsoft To Do | Бесплатный, поддерживает списки, дедлайны, напоминания, синхронизацию | Требует учетную запись, часть пользователей воспринимает интерфейс как избыточный для простых задач | Сделать локальный простой инструмент без регистрации | Пользователь может выбрать готовый зрелый продукт |
| Todoist | Много функций, проекты, метки, приоритеты, удобные приложения | Часть возможностей платная, высокая функциональная сложность для простого списка | Сфокусироваться на минимальном наборе функций: CRUD, категории, JSON | Сильный бренд и широкая экосистема |
| Бумажный блокнот или стикеры | Очень быстрый ввод, не требует устройства и регистрации | Нет поиска, редактирования, автоматической сортировки, сохранения истории | Повторить простоту бумажного списка, добавив поиск и хранение данных | Пользователю может быть достаточно бумажного способа |

## Слепые зоны конкурентов

- Большие цифровые сервисы часто перегружены функциями для пользователя, которому нужен простой личный список.
- Бумажные способы удобны для быстрого ввода, но плохо работают с дедлайнами, поиском и историей выполненных задач.
- Не всем пользователям нужна синхронизация, совместная работа и учетная запись.
- Для учебных задач часто достаточно фиксированных категорий, а не сложной системы проектов, тегов и фильтров.

## Гипотезы для проверки прототипом

1. Если в приложении будут фиксированные категории "Работа", "Учеба", "Личное", то пользователи быстрее будут находить нужные задачи и реже смешивать разные контексты.
2. Если создание задачи будет требовать только название, а описание и дедлайн будут необязательными, то пользователи будут чаще добавлять мелкие задачи сразу после их появления.
3. Если данные будут сохраняться локально в JSON без регистрации и настройки синхронизации, то пользователи, которым нужен простой личный инструмент, будут воспринимать приложение как более легкое и понятное.

## Минимальный набор функций для MVP

- Добавление задачи.
- Просмотр списка задач.
- Редактирование задачи.
- Удаление задачи.
- Отметка задачи как выполненной.
- Категории: "Работа", "Учеба", "Личное".
- Необязательный дедлайн.
- Сохранение и загрузка задач из JSON-файла.
