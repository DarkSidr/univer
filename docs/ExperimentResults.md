# Лабораторная работа №4. Эксперименты и доработка

## Проект

Персональный менеджер задач (Todo List) с категориями.

## Цель

Провести симуляцию A/B теста, доработать MVP на основе результатов эксперимента, добавить интеллектуальную функцию и зафиксировать рефакторинг.

## A/B тест

### Проверяемая задача

В лабораторной работе №4 сравнивались два варианта поиска задач по названию и описанию:

- Version A: поиск через `Contains` с `StringComparison.OrdinalIgnoreCase`;
- Version B: поиск через `Regex` с экранированием пользовательского запроса.

### Реализация

В код добавлен сервис `TaskSearchService`.

Файлы:

- `src/TodoList.Console/Services/TaskSearchService.cs`;
- `src/TodoList.Console/Services/SearchMode.cs`.

В консольное меню добавлены пункты:

- `7. Найти задачу`;
- `8. A/B тест поиска`.

### Методика эксперимента

1. Пользователь вводит поисковый запрос.
2. Приложение выполняет поиск двумя способами:
   - A: `Contains`;
   - B: `Regex`.
3. Каждый вариант выполняется 1000 раз.
4. Приложение измеряет время выполнения через `Stopwatch`.
5. Результат записывается в `analytics.log` событием `search_ab_test_completed`.

Пример события:

```json
{"event":"search_ab_test_completed","user":"local_user","time":"2026-05-07T17:30:00.0000000+05:00","contains_ms":2.1,"regex_ms":7.8,"winner":"Contains"}
```

## Результат эксперимента

Для текущего MVP лучше подходит Version A: `Contains`.

Причины:

- пользовательский запрос воспринимается как обычная строка, а не как регулярное выражение;
- поиск проще объяснить и поддерживать;
- для небольшого локального списка задач `Contains` быстрее и не требует дополнительной обработки шаблонов;
- меньше риск ошибок из-за специальных символов в запросе.

Version B с `Regex` может быть полезна в будущем, если появится расширенный поиск по шаблонам. Для MVP это избыточно.

## Вывод по Pull Request

Условный Pull Request: `feature/version-B -> main`.

Решение:

- оставить оба варианта в коде для демонстрации A/B теста;
- режим `Contains` считать основным для обычного пользовательского поиска;
- `Regex` оставить как экспериментальный режим.

## Интеллектуальная функция

В MVP добавлена локальная интеллектуальная функция: автоматическая классификация важности задачи.

Файл:

- `src/TodoList.Console/Services/TaskImportanceAnalyzer.cs`.

Функция анализирует:

- название задачи;
- описание задачи;
- наличие ключевых слов: "срочно", "важно", "экзамен", "дедлайн", "отчет", "защита", "проект", "оплата";
- близость дедлайна.

Возможные значения:

- `Обычная`;
- `Средняя`;
- `Высокая`.

Пример:

```text
Название: Срочно подготовить отчет
Дедлайн: завтра
Результат: Высокая
```

Данная функция имитирует простую ML/AI-классификацию без внешнего API. Такой подход выбран, чтобы MVP оставался автономным и работал без интернет-доступа, ключей API и платных сервисов.

## Рефакторинг и управление техдолгом

### Что было в MVP

В первой версии логика приложения была сосредоточена вокруг `TodoService` и консольного меню:

- CRUD;
- логирование;
- подготовка данных для отображения;
- часть логики будущего поиска могла попасть в меню.

### Что изменено

Добавлены отдельные классы:

- `TaskSearchService` - поиск задач и A/B benchmark;
- `TaskImportanceAnalyzer` - классификация важности задачи;
- `SearchMode` - явное перечисление вариантов поиска.

### Какой технический долг устранен

- Поиск не смешан с консольным интерфейсом.
- Логика анализа важности не встроена напрямую в CRUD.
- Сервис задач остался ответственным за управление задачами, а не за алгоритмы поиска.
- Экспериментальная логика A/B теста оформлена отдельным методом и может быть удалена или расширена без переписывания CRUD.

## Новые события аналитики

| Событие | Назначение |
| --- | --- |
| `task_search_used` | Фиксирует использование поиска, режим и количество результатов |
| `search_ab_test_completed` | Фиксирует время Version A и Version B, а также победителя |
| `task_created` | Теперь дополнительно содержит поле `importance` |
| `task_updated` | Теперь дополнительно содержит поле `importance` |

## Использование AI

AI-ассистент использовался как аналог GitHub Copilot для:

- генерации структуры A/B benchmark;
- выбора критериев сравнения `Contains` и `Regex`;
- подготовки интеллектуальной функции оценки важности;
- предложения рефакторинга через выделение `TaskSearchService` и `TaskImportanceAnalyzer`;
- оформления результатов эксперимента.
